# Deribit Grid

Компактный Windows-бот на C++20 и Qt 6. Один инструмент на окно, отдельные профили для BTC и ETH. Интерфейс, сообщения и комментарии на английском.

## Запуск

Дважды щёлкните `start.cmd` в корне проекта. Он автоматически запускает готовый EXE из `dist`. В стартовом окне настроек выберите BTC или ETH и среду; по умолчанию выбрана Testnet. Нажмите **Open**. Для одновременной работы BTC и ETH запустите тот же `start.cmd` ещё раз и выберите другой инструмент.

Тот же `start.cmd` работает внутри `dist`; можно также открыть `dist/DeribitGrid.exe` напрямую. Запуск не зависит от текущей папки терминала. Для запуска Python и установленный Qt не нужны. Папку `dist` нужно переносить целиком, вместе с DLL и подкаталогами.

Программа сама выбирает профиль рядом с EXE: `profiles/btc-test.db`, `profiles/eth-test.db`, а для Production — `profiles/btc-prod.db` и `profiles/eth-prod.db`. Существующие профили сохраняются. Чтобы сменить инструмент или среду, закройте окно и запустите программу снова. Не удаляйте базу действующей сетки: в ней находится связь между собственными входами и тейками.

1. Укажите границы, бюджет **номинала входов** в USDC и число интервалов отдельно для Long и Short. Бюджет 0 отключает сторону. Диапазоны не пересекаются; общая граница относится к Short.
2. Оставьте Testnet. Введите тестовые Client ID и Client secret в окне программы и нажмите **Connect**. Для Production нужен отдельный профиль и ключ соответствующей среды.
3. Дождитесь **Connected** и актуальной цены. Затем **Start / Resume** запускает сетку. **Apply settings / Rebuild** сохраняет старые тейки и перестраивает свободную часть.
4. **Pause (keep takes)** отменяет входы, оставляя тейки. **Cancel all bot orders** отменяет также тейки, но не закрывает позицию.
5. **Clear log** очищает только журнал внизу окна. **Reset after manual trades** сбрасывает сохранённые циклы, ордера и локальный инвентарь после ручного вмешательства. Кнопка доступна только на паузе и после подтверждённой отмены всех заявок бота; перед сбросом открытые заявки и позиция ещё раз проверяются через API. Настройки, привязка профиля и счётчики текущего запуска сохраняются. Биржевая позиция не закрывается и не включается в новые циклы. После сброса нажмите **Start / Resume** для новой сетки.

Secret не сохраняется в SQLite и не записывается в журнал. Ключу нужны `trade:read_write`, чтение аккаунта и `account:read_write` для отключения Cancel-on-Disconnect текущего соединения. Прав на вывод средств не требуется. Один профиль привязывается к аккаунту, среде и инструменту.

## Механика

Флажок **Preview pending settings** показывает уровни и ориентировочные количества для введённых настроек до их применения. Снятый флажок показывает действующую сетку. Предпросмотр доступен после получения спецификации и текущей цены.

Справа отображаются **Approx. P&L** в USDC и **Closed trades** за текущий запуск программы. Для Long прибыль считается как `(тейк − вход) × исполненное количество монет`, для Short — `(вход − тейк) × количество`. Используются цены уровней сетки, без комиссий, funding и улучшения цены исполнения. Частичные исполнения тейков сразу увеличивают P&L; полностью исполненная тейк-заявка считается одной закрытой сделкой. Повторные уведомления не увеличивают счётчики. Чужие сделки и исполнения до первого подключения не включаются. Счётчики хранятся только в памяти: пауза, перестройка и переподключение их сохраняют, закрытие программы сбрасывает. Текст можно выделить и скопировать для записи в Excel.

**Fees (entry + take)** — отдельная сумма фактических комиссий в USDC за исполнения входов и тейков после первой сверки этого запуска. Бот берёт `fee` и `fee_currency` из уведомлений о сделках и ответов торговых запросов; недостающие данные запрашивает через `private/get_user_trades_by_order`. Частичные исполнения суммируются, повторы по `trade_id` учитываются один раз, отрицательные комиссии (rebates) уменьшают сумму. Уже уплаченные комиссии старых исполнений и чужих ордеров не включаются. При неполных данных появляется **(incomplete)**; это не останавливает торговлю, P&L по-прежнему отображается валовым. Переподключение повторяет запрос недостающих комиссий. Funding в этот счётчик не входит; комиссии входов учитываются сразу, даже если позиция ещё не закрыта. В базе этот счётчик не сохраняется.

Кнопка **Reset stats** в верхнем ряду кнопок обнуляет P&L, комиссии и закрытые сделки без подтверждения, начиная новый период статистики. Ордера, позиции, настройки и работа сетки сохраняются. Последующие исполнения тейков увеличивают P&L и число закрытых сделок; комиссии учитываются для сделок с отметкой времени начиная со сброса. Старые запросы недостающих комиссий и их запоздавшие ответы исключаются из нового периода. Повторные уведомления не возвращают уже сброшенные суммы. Сброс статистики отличается от **Reset after manual trades**, который очищает торговую историю и инвентарь.

Цена берётся как середина best bid / best ask. При запуске строятся **обе сетки сразу**: Long и Short, если их бюджеты больше нуля. Продажи стоят в шортовом диапазоне, покупки — в лонговом. Свободные входы Long автоматически перестраиваются после роста на шаг последней построенной сетки, Short — после падения на шаг. При приближении цены уровни сохраняются. Неизменившиеся после округления уровни не отменяются. Разворот на один ценовой тик во время переноса прекращает перестройку; отменённые свободные входы восстанавливаются на прежних уровнях. Start / Resume и Apply settings / Rebuild явно перестраивают обе стороны. Начальные заявки двух сторон отправляются поочерёдно, с ограничением частоты API.

Расчёт выполняется отдельно для каждой стороны. Если текущая цена внутри её диапазона, X — текущая цена. Если цена вне диапазона, X — верхняя граница Long либо нижняя граница Short; эта сторона строится по всему диапазону. Y — нижняя граница Long либо верхняя граница Short. Шаг `abs(Y-X)/N`. Для Short входы выше X, тейк на соседнем уровне ниже; для Long зеркально. Цены округляются к разрешённым тикам в пределах диапазона. Слишком плотная сетка блокируется. Новый или повторный вход отправляется только ниже текущей цены для Long либо выше для Short; остальные уровни ждут. Уже работающие входы сохраняются.

Счётчик в строке статуса показывает свободные слоты позиции: `max(0, N − число циклов с незакрытым объёмом) / N`, включая старые циклы. Частичный вход занимает один слот до закрытия остатка. Для ограничения размещений N отдельно ограничивает логические циклы, а не количество биржевых заявок. Старые незакрытые циклы занимают места. При закрытии старого тейка освобождённое место используется на свободном уровне текущей сетки. Шаг при этом не пересчитывается. Свободный бюджет делится между свободными слотами; после округления часть бюджета может остаться неиспользованной.

Частичный вход сразу получает тейк на исполненное количество BTC/ETH. Частичный тейк освобождает такой же объём для повторного входа текущего цикла. Остатки одного цикла объединяются посредством редактирования его заявки. У старых циклов после перестройки сохраняются цены и количества тейков, а входы на старых ценах больше не повторяются.

Учитывается незакрытый объём по входным уровням плюс резерв входов. Это не маржа и не потолок рыночной стоимости. При уменьшении лимитов ниже занятого объёма новые входы запрещаются, старые тейки остаются.

Все заявки — обычные limit/GTC с `post_only=false`. Рыночных заявок, STOP-LOSS и автоматического закрытия нет. Лимитная заявка может исполниться как taker. Тейки — обычные LMT, без универсального `reduce_only`: Deribit ведёт общую нетто-позицию инструмента, а две части сетки учитываются внутри бота. Ручной хедж бот автоматически в свои циклы не принимает.

## Пауза, восстановление и ошибки

При нормальном закрытии программа ждёт отмены входов и выставления тейков на исполнения, произошедшие во время отмены. При аварии или обрыве связи все уже принятые биржей заявки остаются. Пока программа отключена, она не может выставлять новые тейки.

После подключения сверяются сохранённые незавершённые ордера. Для потерянного ответа сначала ищется ордер по сохранённой метке; без подтверждённого результата запрос не повторяется. Неразрешённый ордер блокирует дальнейшие действия и требует проверки. Если биржевая история уже недоступна, бот также не угадывает состояние.

При расхождении позиции во время работы бот даёт 200 мс на запаздывающее уведомление об исполнении, продолжая обслуживать заявки. Если учтённый объём изменился, устаревший снимок позиции не запускает полную сверку. Сверка использует общий список открытых ордеров; отдельно запрашиваются отсутствующие ордера и неопределённые результаты запросов. При успешной сверке работающая сетка продолжает работу, восстановленные исполнения получают тейки перед запросами комиссий. При устойчивом расхождении журнал показывает фактическую позицию, объём бота, внешний объём, ожидаемую позицию и разницу. Сторонние исполнения не изменяют сохранённый внешний объём автоматически.

До восстановления тейков и отправки новых входов сверяется общая позиция с локальным инвентарём: Long со знаком плюс, Short со знаком минус, плюс сохранённая внешняя позиция. **Net position** показывает весь инструмент в аккаунте; объёмы циклов видны в таблице. При первом подключении пустого профиля ручная позиция сохраняется как внешний объём; при последующих запусках этот объём не подменяется автоматически. Для старых профилей с незакрытым инвентарём неизвестная ручная составляющая не угадывается. При расхождении появляется **Position mismatch**, бот отменяет свои входы и запрещает создание или изменение тейков. Уже стоящие тейки сохраняются до явного **Cancel all bot orders**. Позиция и чужие ордера сохраняются. Это предотвращает создание новых лимитных тейков для уже закрытой вручную позиции; сохранённые заявки при подходящей рыночной цене всё равно могут исполниться. После проверки ручных действий отмените заявки бота и используйте **Reset after manual trades** либо восстановите согласованность позиции и нажмите **Reconnect / Reconcile**. Сверка проверяет нетто-объём, а не восстанавливает историю ручных сделок.

Тейки имеют приоритет перед встречными входами бота. Мешающие входы отменяются. При конфликте с ручным ордером или другим тейком отображается ожидание. Учитываются обычные и условные ручные заявки. Входы в направлении ручного `reduce_only`-тейка ждут, чтобы не уменьшать позицию, которую он должен закрыть. Для условного рыночного тейка без лимитной цены встречные входы также ждут. Чужие ордера не отменяются и не редактируются; перед торговым запросом проверяется связь ордера с текущим профилем. Уже стоящий тейк бота при перезапуске сверяется по ID, сохраняя цену и объём, если новых исполнений нет. В журнале торговых запросов виден ID ордера или его метка, а в уведомлениях об отмене чужого ордера — причина биржи, если она передана. Ручная отмена заявки бота требует явного Resume после проверки. Не редактируйте объём или цену собственных ордеров бота во время его работы.

Если нормальная отмена не может завершиться из-за отсутствия связи, при закрытии программа явно предлагает оставить биржевые заявки как есть. Состояние SQLite проверяется при чтении; ошибка записи запрещает новые запросы. Версии профилей 1–3 читаются и при следующей записи переводятся в версию 4 с точными JSON integers. Активные записи и последние 1000 завершённых ордеров остаются в памяти, остальные атомарно архивируются в SQLite. Поздние исполнения восстанавливаются из архива и учитываются по приросту исполненного объёма. Дедупликация комиссий хранится во временных таблицах текущего запуска.

## Сборка и тесты

Нужны Visual Studio 2022 с C++ x64/Windows SDK/CMake, Qt 6.8+ MSVC x64 с Qt WebSockets и Python 3 для удобного сценария сборки. Python используется только при сборке, сам бот написан на C++. Точная арифметика использует заголовки Boost 1.89.0; перед первой сборкой выполните `python scripts/dependencies.py`.

```powershell
python scripts/build.py
# Другой путь к Qt:
python scripts/build.py --qt C:/Qt/6.8.3/msvc2022_64
# Только движок и его тесты, без Qt:
python scripts/build.py --core-only
```

В этом проекте Qt установлен локально в `.deps/Qt/6.8.3/msvc2022_64`. Сценарий создаёт Release-сборку, запускает CTest и собирает каталог `dist` с зависимостями. Обновление допускается только при закрытых окнах DeribitGrid; перед заменой EXE сохраняются предыдущий EXE и согласованные SQLite-снимки профилей в `build/deployment-backups`. Для проверки памяти используйте `python scripts/build.py --asan --skip-deploy`, для замеров — `python scripts/build.py --benchmarks --skip-deploy`. Исходный пустой `.sln` сохранён; для работы в Visual Studio откройте папку с `CMakeLists.txt` либо сгенерированный `build/app/DeribitGrid.sln`.

Проверки покрывают частичные исполнения, повторы событий, отмену с исполнением, бюджет, старые слоты, смену диапазонов, потерянный ответ, SQLite и WebSocket JSON-RPC на локальном сервере. `testnet_probe` делает только публичные read-only запросы спецификаций BTC/ETH к настоящему Testnet. Частная авторизация и реальное выставление/отмена тестовых ордеров требуют ваших Testnet-ключей и отдельной проверки через приложение; локальные тесты этого не подтверждают.

```powershell
# В окружении с Qt DLL в PATH:
build/app/Release/testnet_probe.exe
dist/DeribitGrid.exe --profile profiles/btc-test.db --instrument BTC_USDC-PERPETUAL
dist/DeribitGrid.exe --profile profiles/eth-test.db --instrument ETH_USDC-PERPETUAL
```

Официальные источники: [Deribit API](https://docs.deribit.com/), [спецификации linear perpetual](https://support.deribit.com/hc/en-us/articles/31424969384605-Linear-Perpetual). Python-wrapper не включён в приложение.
